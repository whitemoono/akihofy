### 1.3 数据流向

```
用户输入
  │
  ├─→ 体验模拟层：评估刺激对"我"意味着什么
  │     │
  │     ├─► 情感体验（不只是 PAD 值，而是情感反应链）
  │     ├─► 欲望激活（哪些需求被触发）
  │     ├─► 价值观审查（是否符合我的原则）
  │     └─► 内心独白（我真正在想什么）
  │
  ├─→ 状态计算层：更新可观测状态
  │     └─► PAD值、资源池、记忆等
  │
  ▼
Python 层：构建 LLM 上下文
  ├── 体验结果（来自体验模拟层）
  ├── 当前情绪状态（来自状态计算层）
  ├── 相关记忆片段（来自状态计算层）
  └── 生理状态、关系状态、成长阶段（来自状态计算层）
  │
  ▼
LLM 接收的是"体验结果"而非简单的"状态数值"
  │
  ▼
Response + 状态持久化
```

### 1.4 拟人化核心设计原则

> 拟人化的本质：不是预设人格，而是让角色从交互中**生长**出独特性格。不是被动响应机器，而是一个有自主意识的数字存在。

| 原则 | 说明 |
|------|------|
| **体验先于表现** | 先模拟真实的情感体验过程，再生成语言表达。情绪不是状态值，而是一连串的情感反应链 |
| **欲望驱动行为** | 由内部欲望（想社交/想独处/想创造）驱动，而非简单的规则触发。欲望来源于未满足的需求 |
| **叙事构成自我** | 角色通过积累的人生故事形成独特的自我认知。记忆不只是信息存储，而是"经历过的体验" |
| **价值观作为硬约束** | 所有行为必须通过价值观审查，而非仅靠 LLM 自由生成。角色有底线和坚持 |
| **内部独白真实** | 不是给 LLM 的上下文提示，而是角色真正在思考的声音——那些没说出口的想法 |

## 二、技术选型

### 2.1 技术栈总表

| 层级 | 组件 | 技术选型 | 理由 |
|------|------|----------|------|
| **表现层** | 前端 | React + TypeScript | 类型安全，组件化 |
| | 实时通信 | WebSocket | 双向实时通信 |
| | 监控面板 | 自定义 React 组件 | 实时状态可视化 |
| **Python层** | Web框架 | FastAPI | 异步、高性能、自动文档 |
| | LLM封装 | OpenAI SDK / Anthropic | 官方SDK |
| | 调度器 | APScheduler | 离线任务调度 |
| | 异步运行 | asyncio + uvicorn | 高并发 |
| **Rust层** | 核心引擎 | Rust + PyO3 | 性能、内存安全、GIL释放 |
| | 向量计算 | candle-core | 轻量高效 |
| | 序列化 | serde | 成熟的序列化库 |
| **数据层** | 关系数据库 | PostgreSQL | 关系数据、事务 |
| | 缓存 | Redis | 实时状态、Pub/Sub、会话 |
| | 向量数据库 | ChromaDB | 轻量、Python原生 |
| | 文件存储 | S3/MinIO | 媒体文件、备份 |

### 2.2 为什么选择 Python + Rust

| 考量 | Python | Rust |
|------|--------|------|
| **LLM生态** | ★★★★★ 原生支持 | ★★ 需要封装 |
| **实时性能** | ★★ GIL限制 | ★★★★★ 无GC停顿 |
| **内存效率** | ★★ GC开销大 | ★★★★★ 零成本抽象 |
| **开发速度** | ★★★★★ | ★★★ 学习曲线 |
| **并发模型** | ★★★ asyncio | ★★★★★ 原生并发 |

**结论**: Python 处理 LLM 交互和业务逻辑，Rust 处理高性能实时系统。

## 四、十六、实现优先级

### 4.1 优先级定义

| 优先级 | 标识 | 含义 | 目标 |
|--------|------|------|------|
| P0 | 关键 | 必须实现，阻塞其他功能 | MVP |
| P1 | 重要 | 应该实现，提升体验 | V1.0 |
| P2 | 增强 | 可以实现，锦上添花 | V1.1+ |
| P3 | 未来 | 长期规划，MVP后考虑 | 路线图 |

### 4.2 分阶段实现计划

#### **Phase 0: 基础设施** (1-2周)

| 模块 | 优先级 | 工作项 | 依赖 |
|------|--------|--------|------|
| 项目结构 | P0 | 搭建目录、配置CI/CD | 无 |
| Rust基础 | P0 | akiho-core框架、错误处理 | 无 |
| Python-Rust桥接 | P0 | PyO3绑定、Maturin配置 | Rust基础 |
| 数据库连接 | P0 | PostgreSQL/Redis连接 | 无 |
| 日志系统 | P1 | 结构化日志、追踪 | 无 |

#### **Phase 1: 核心引擎 MVP** (2-4周)

| 模块 | 优先级 | 工作项 | 依赖 |
|------|--------|--------|------|
| 情绪系统 | P0 | PAD模型、状态机、刺激响应 | Phase0 |
| 记忆系统 | P0 | 存储、检索、向量索引 | Phase0 |
| 行为系统 | P0 | 行为注册、决策算法 | 情绪系统 |
| LLM封装 | P0 | OpenAI/DeepSeek适配器 | Phase0 |
| API服务 | P0 | 聊天接口、WebSocket | Phase0 |

#### **Phase 2: 智能系统 V1.0** (3-4周)

| 模块 | 优先级 | 工作项 | 依赖 |
|------|--------|--------|------|
| 自主性系统 | P0 | 内部驱动、思考循环 | 情绪+行为 |
| 人格成长 | P1 | 成长阶段、学习机制 | 记忆系统 |
| 生理系统 | P1 | 能量、疲劳模型 | 情绪系统 |
| 认知系统 | P1 | 注意力、推理 | Phase1 |
| 离线处理 | P2 | 任务调度、后台处理 | Phase1 |

#### **Phase 3: 关系系统 V1.1** (2-3周)

| 模块 | 优先级 | 工作项 | 依赖 |
|------|--------|--------|------|
| 关系模型 | P1 | 信任、亲密度 | Phase1 |
| 自我思考 | P1 | 反思、内心独白 | 自主性+认知 |
| API缓存 | P1 | Token缓存、响应缓存 | Phase1 |
| 性能优化 | P1 | 向量索引、连接池 | Phase1 |

#### **Phase 4: 高级功能 V1.2+** (持续)

## 六、快速开始

### 6.1 环境要求

- Python 3.11+
- Rust 1.75+
- PostgreSQL 15+
- Redis 7+
- Docker (可选)

### 6.2 Docker 部署（推荐）

```bash
# 1. 复制环境变量配置
cp .env.example .env
# 编辑 .env 填入 API keys

# 2. 一键启动所有服务
docker-compose up -d

# 3. 查看日志
docker-compose logs -f app

# 4. 访问
# 前端: http://localhost:5173
# API: http://localhost:8000
# API Docs: http://localhost:8000/docs
```

### 6.3 手动部署

```bash
# 1. 克隆项目
git clone https://github.com/your-username/AKIHO.git
cd AKIHO

# 2. 安装 Python 依赖
pip install -r requirements.txt

# 3. 安装 Rust 依赖
cargo build --release

# 4. 构建 Python 绑定
cd akiho-core/python
maturin develop --release

# 5. 配置环境变量
cp .env.example .env
# 编辑 .env 填入 API keys

# 6. 启动服务
uvicorn api_server:app --reload --host 0.0.0.0 --port 8000
```

### 6.4 验证安装

```bash
# 测试 API
curl http://localhost:8000/health

# 测试 WebSocket
# 使用前端界面连接 ws://localhost:8000/ws

# 测试 Rust 绑定
python -c "from akiho_core import EmotionEngine; print('Rust binding OK')"
```
